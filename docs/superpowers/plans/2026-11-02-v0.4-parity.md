# peephole-android v0.4 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Bring the app's IP page to web parity through the 0.23 dossiers, add ASN / campaign / request screens, a light + system theme and small polish, then release v0.4.0.

**Architecture:** New typed dossier models and API calls in `net/`; pure, unit-tested helpers (signals, chart bucketing, fallback, prop chips) beside thin Compose screens; theme colours move into a `CompositionLocal`. No new dependency.

**Tech Stack:** Kotlin, Jetpack Compose Material 3, kotlinx.serialization, OkHttp, JUnit 4 + MockWebServer.

**Spec:** `docs/superpowers/specs/2026-11-02-v0.4-parity-design.md`

## Global Constraints

- No new library and no change to `gradle/verification-metadata.xml`.
- Every model field has a default; `PeepholeApi.json` keeps `ignoreUnknownKeys`.
- Attacker text (request target, headers, body, UA, event summaries, commands, upload names) is shown only as plain `Text`; never linked, never opened, never written to disk.
- Token never logged; nothing new in backup.
- minSdk 26, compileSdk 37 unchanged. Package `io.github.overcuriousity.peephole`.
- Colours only from the theme (`MaterialTheme.colorScheme` or `LocalPeepholeColors`), spacing from `Spacing`.
- Verification runs only in CI (`./gradlew assembleDebug assembleRelease lintDebug testDebugUnitTest`); the container cannot reach dl.google.com. Open a draft PR after Task 1 so every push runs CI; a task is done when CI is green on its last commit.

## Review Focus

- IPv6 addresses and IPv6 campaign keys must be one path segment (`2001:db8::1`) — test in Task 1.
- A minimal dossier (only envelope + `ip`, every list missing, `props`/`evidence`/`sharing`/`campaign` null) must decode and render with those sections hidden — decode test in Task 1, `propChips(null, false)` test in Task 5.
- Sparse `week`/`calendar` (only hours/days with requests; entries older than the window; malformed `ts`) must fill zeros and drop what is out of range or unparsable — tests in Task 4.
- A stored theme value that is unknown or missing reads as System — test in Task 3.
- A request with an empty `body_text` but non-empty `body_b64`, and one with neither — test in Task 6.
