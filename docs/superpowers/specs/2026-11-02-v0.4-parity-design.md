# peephole-android v0.4: closer to the web

Status: approved in chat 2026-11-02, written for review.

## Goal

The app lags the peephole web UI (server 0.23.2). Server 0.23.0 added
read-scope dossiers (`/api/v1/{ips,asns,requests,campaigns}/…/dossier`)
that carry nearly everything the web IP page shows; the app uses none of
them. v0.4.0 closes that gap with no server change, adds the web's light
theme, and fixes small rough edges.

Owner decisions:

- Scope: IP page parity, pivot screens (ASN, campaign, request), light +
  system theme, small polish.
- Enrichment: only the signals strip is ported; the raw per-provider
  key/value list stays below it. No port of the server's `intel_facts`.
- Release: Claude opens the PR, merges it once CI is green, tags
  `v0.4.0` on the merge commit and checks the release.

Out of scope (need api-v1 changes): job list, job cancel, IP-list filters
beyond `q`, credit balance.

## 1. Data layer (`net/`)

`PeepholeApi` gains:

| call | route |
|---|---|
| `ipDossier(addr)` | `GET /api/v1/ips/{addr}/dossier` |
| `asnDossier(n)` | `GET /api/v1/asns/{n}/dossier` |
| `campaignDossier(key)` | `GET /api/v1/campaigns/{key}/dossier` |
| `requestDossier(id)` | `GET /api/v1/requests/{id}/dossier` |

Each returns the decoded model and the response text (`Dossier<T>(value,
raw)`), so Share sends exactly what the server sent. Models live in a new
`net/Dossiers.kt`; every field has a default, unknown keys are ignored.
`IpDetail` and `IpSummary` gain `is_tor_relay` and `unseen`.

IP fallback, a pure function over two results so it is unit-testable:

- dossier `Ok` → full page.
- dossier `404` → call `GET /ips/{addr}`: `404` → "not in the dataset";
  `Ok` → server older than 0.23, page without the dossier sections, plus
  one line saying the instance is older than 0.23.
- anything else → that error.

Pivot screens on an older server (404 with the catch-all `not_found` and
no other way to tell) show "Not found on this instance (needs peephole
0.23 or newer)".

### Signals

`signalsOf(detail: IpDetail): List<Signal>` in `ui/Signals.kt`, a port of
peephole `src/admin/signals.rs` that reads the raw provider JSON:

| source | signal | tone |
|---|---|---|
| `is_tor` | Tor exit = listed / no | bad / ok |
| `is_tor_relay` (not exit) | Tor relay = listed | warn |
| `abuseipdb.score` (int) | Abuse = n/100, meter n | ≥75 bad, ≥25 warn, else ok |
| `shodan`, `shodan-internetdb` `ports` (array) | Shodan / InternetDB = n open port(s) | info |
| same, object with no non-null field | … = nothing known | ok |
| same, `vulns` (array) | CVEs = n | bad |
| `rdap` `name`, `type` | Registry = "name · type" | info |
| `rdap.fresh == true` | Block = new, under 90 days | warn |

Order: Tor, then providers in the server's card order (abuseipdb, shodan,
shodan-internetdb, rdap). Unknown providers add nothing. (api-v1 leaves
`tor-exits` out of `intel`; `is_tor` is its reading.)

## 2. IP detail screen

`IpDetailScreen` is split: screen + loading in `IpDetailScreen.kt`,
sections in `IpSections.kt`, charts in `ActivityCharts.kt`. Order, top to
bottom:

1. Header: address (selectable, Copy), property chips from `props` (Tor,
   net kind, scanner, fleet, agent, "not scanned" / "scan pending") and
   `unseen` ("added by an operator"); country; ASN line (tap → ASN
   screen); campaign chip "campaign #num" (tap → campaign screen); first /
   last seen UTC.
2. Tiles: requests, rank, max severity, open ports of the newest scan.
3. Signals strip (toned chips, meter on Abuse); below it the current raw
   enrichment list in a collapsed "Provider answers" section.
4. Evidence and Address sharing: label, sentence, note, caveat, lines
   (kind, what, port, source, date).
5. Activity: 7-day hourly bars (`week`, stacked by severity) and a
   26-week day calendar (`calendar`, coloured by max severity), Compose
   `Canvas`, no new dependency; content description gives totals.
6. Timeline: `events`, newest first, first 50 with "Show all"; a
   `request` row opens the request screen; attacker text is plain text.
   "Older events not shown" when `truncated.events`.
7. Probes history (`probes`), Scans (existing level picker), Probe
   action.
8. Lures: uploads (metadata only), webshell commands, canary reuse;
   hidden when all empty.
9. Names and neighbours (unchanged).

App bar: Share menu, "Address" (plain text) and "Dossier JSON" (raw text
via `ACTION_SEND`; nothing written to disk).

## 3. Pivot screens

New routes, all through `Paired`:

- `instance/{id}/asn/{n}`: org, IPs, requests, max severity, first/last
  seen, labels with IP counts, open ports with IP counts, campaigns (tap →
  campaign), top IPs as `IpRow` (tap → IP). "Showing the busiest 50 of N"
  when `truncated.ips`.
- `instance/{id}/campaign/{key}`: number, size, first/last seen, edge
  counts; members (tap → IP); shapes; calendar (same chart as the IP);
  commands; events with their `ip`. Edges as a count only, no graph.
- `instance/{id}/request/{rid}`: method + target, time, IP (tap → IP),
  answer, status, severity, labels, OWASP, persona, transport, JA4/JA4H,
  UA; headers and body as selectable mono text, never linked or rendered
  (`body_truncated` noted; `body_b64` only shown as "binary body, n
  bytes" when `body_text` is empty); `same_ip` and `same_ja4.recent`
  (tap → request); campaign chip.

## 4. Theme

- `ui/Theme.kt` gets the light palette from peephole
  `assets/css/00-tokens.css` (bg #f6f5f0, surface #efede6, elevated
  #ffffff, fg #1f2024 / #4f5159, border #d9d5c9, accent #1f6f8b, brand
  #b30000, danger #b3382c, warning #845b16, success #2b7048, severity
  #63656c #7f6100 #b04a00 #b31c1c #7a1fa2) next to the existing dark one.
- `Success`, `Warning`, severity and signal tones move into a
  `PeepholeColors` data class provided by `LocalPeepholeColors`.
- Mode System / Light / Dark in `ThemePrefs` (plain SharedPreferences,
  not secret, not backed-up-sensitive). Picked in a new "Appearance"
  dialog from Home's top bar. Status/navigation bar icons follow the
  mode.

## 5. Polish

- Vendored Material Symbols `ic_arrow_back` (autoMirrored) replaces the
  `←` glyph; `ic_open_in_new` is not added (nothing is opened).
- `summaryLine` shows "tor relay" and "unseen".
- Lookup "Stored" rows add last seen.
- `versionName` default `0.4.0-dev`; README and roadmap updated.

## Testing

JVM unit tests (CI only; the container cannot reach the Android SDK):

- `SignalsTest`: the server's two test cases translated, plus relay and
  empty-provider cases.
- `DossiersTest`: decoding fixture JSON for the four kinds shaped as in
  peephole `docs/api-v1.md`, including missing optional fields.
- `PeepholeApiTest`: dossier routes and the 404 fallback with
  MockWebServer.
- `ActivityChartsTest`: week/calendar bucketing into grid positions
  (pure functions).

## Risks

- No local build: compile and lint failures surface only in CI.
- Signals rules can drift from the server's; they are small and tested
  against the server's own cases.
- Dossier shapes are taken from the docs and `src/admin/dossier.rs`; no
  live 0.23 instance was used.
